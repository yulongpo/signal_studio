# MS-03 实施记录

## 1. 公共模块契约

`include/signal_studio/visualization/visualization.hpp` 新增纯 C++20 的 Visualization 公共 API：

- `ViewportController` 统一真实已读时间范围、当前时间视口、有效/当前频率范围、部分数据状态、字节数和请求代际；
- `AtomicFrameCoordinator` 只接受当前 `ViewRequestId` 的时域、PSD、STFT 原子帧，拒绝过期结果；
- `LayerModel`、`DisplayMapping`、`OverlayModel`、`VisibilityController` 和 `ChartLayoutModel` 分别负责图层、显示映射、Selection/测量、隐藏计算边界和图表顺序/高度；
- `IAnalysisWorkspace` 是 Qt 无关的宿主接口，暴露视口、帧、交互、Selection、截图和可访问摘要。

`include/signal_studio/workbench/workbench.hpp` 新增纯 C++20 的 Workbench 公共 API：

- 服务、命令和面板注册表；
- 诊断、主题、参数、模态行为和布局序列化；
- Inspector、任务中心、结果中心和状态的 `WorkbenchContent` 注入模型；
- `IWorkbenchWindow` 的显示、布局恢复/保存和本机句柄边界。

公共头没有 Qt、Eigen、oneMKL、CUDA、HDF5、ONNX Runtime、FFTW 或标准库实现类型。Qt Core/Widgets 仍只在 Visualization/Workbench 私有链接边界出现，模块 DAG 未改变。

## 2. Qt 可视化实现

`qt_visualization.cpp` 实现真实 Qt Widgets 工作区：

- 时间导航条使用实际已读范围，支持窗口拖动、两端调整、滚轮、方向键、PageUp/PageDown、Home/End 和完整焦点语义；
- 时域、PSD 和 STFT Canvas 真实绘制当前帧；频谱/瀑布、星座和眼图作为完整可复用组件集合提供；
- PSD 与 STFT 共享同一精确整数 Hz 频率视口；滚轮只缩放频率横轴，平移保持带宽，右键正向框选裁剪、反向拖动恢复；
- 频率输入支持 Hz、kHz、MHz、GHz 并保留整数 Hz 精度，时间和频率 Selection 可通过对话框精确输入；
- 时域支持实部、I/Q、幅度和相位显示；频谱支持单边、镜像双边和 `fftshift` 双边；
- 图层、色阶、参考电平、动态范围、游标、Selection、测量、截图组成项、显示/隐藏、布局高度和位置均有真实状态；
- 隐藏视图断开观察、清空待准备并停止专属绘制；显示映射不修改底层数值结果；
- Canvas 提供可访问名称、描述和文本摘要，高频命中区不小于 28×28 逻辑像素。

## 3. Qt 工作台实现

`qt_workbench.cpp` 实现主窗口、菜单、工具栏、Dock、Inspector、任务中心、结果中心、设置、诊断、通知状态和状态栏。命令具有统一 ID、文本、快捷键和处理器；Dock 布局可序列化、恢复和保存；主题令牌由公共配置注入。

生产 `WorkbenchConfiguration` 默认使用真实空状态，不包含 `x310-demo`、虚构任务或结果。演示程序在 `examples/visualization_workbench_demo.cpp` 中显式构造演示帧与
`WorkbenchContent`，因此截图内容不污染平台库的产品语义。

## 4. Qt Designer 与预览

生产构建通过 `qt_wrap_ui` 使用以下六个 `.ui` 文件：

- `SignalWorkbenchMainWindow.ui`
- `SignalInspectorPanel.ui`
- `SignalTaskCenterPanel.ui`
- `SignalResultCenterPanel.ui`
- `SignalSettingsPanel.ui`
- `SignalDiagnosticsPanel.ui`

文件使用布局管理器并通过 `uic` 实际生成编译输入。自动截图脚本在默认 Windows 平台运行演示程序，生成 1280×720、1600×900、1920×1080 和 200% DPI 四组真实截图；索引、Designer 打开方式和应用启动方式见
`docs/development/ui-preview/MS-03_UI预览索引.md`。

## 5. Qt 平台插件故障整改

针对 Debug 启动时 `QApplication` 报告“no Qt platform plugin could be initialized”的问题，CMake 现在对演示程序和 Qt 测试目标部署：

- 配置匹配的 `Qt6Core[d].dll`、`Qt6Gui[d].dll`、`Qt6Widgets[d].dll`；
- `platforms/qwindows[d].dll` 和 `platforms/qoffscreen[d].dll`；
- 声明 `Prefix=.`、`Plugins=.` 的 `qt.conf`。

安装树同样包含这些运行时材料。自动化清空 `QT_QPA_PLATFORM`、`QT_PLUGIN_PATH` 和
`QT_QPA_PLATFORM_PLUGIN_PATH` 后，构建树与安装消费者都由默认 Windows 平台成功初始化，修复不依赖开发者机器环境变量。

## 6. 构建、安装与持续集成

根 CMake 新增两个生产源集合、UI 包装、演示目标、Qt 运行时部署/安装和 MS-03 测试。安装消费者实际创建视口、图层、工作台布局和内容，并启动已安装演示程序。GitHub Actions 的 Qt/UI 作业增加 MS-03 需求集合，Windows 无界面作业保持无 Qt。

本机 CUDA 路径继续固定为 Toolkit 12.4.131；MS-03 不需要 cuDNN，也没有自动安装任何 CUDA 或 cuDNN 组件。Qt 使用
`D:\softwares\Qt\6.11.1\msvc2022_64`。按用户决定未执行 Ubuntu 24.04 无界面测试。
