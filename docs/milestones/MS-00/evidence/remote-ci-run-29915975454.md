## 根因与本地修正

1. Python 3.14 在 Windows runner 使用 `cp1252` 输出中文外部数据路径时抛出 `UnicodeEncodeError`。工作流和 CTest 现固定 UTF-8，校验器也会安全重配置标准流。
2. `test_data/minimal/manifest.json` 在 Windows 检出后变为 CRLF，和生成器的 LF 输出不一致。Git 属性现固定 LF；生成器使用排序 JSON、POSIX 路径、UTF-8 无 BOM，并增加规范性回归。
3. 公共 PowerShell 脚本只接受本机 BuildTools 固定路径。现优先复用已初始化环境，再检查 `VSINSTALLDIR`、`vswhere.exe` 的最新 VS2022 C++ 安装，最后才使用本机后备路径。
4. Qt 6.11.1 的既有 Action 元数据地址返回 404。官方 Qt 6.10.3 `Updates.xml` 返回 200，并包含 `qt.qt6.6103.win64_msvc2022_64`，因此 CI 改用 6.10.3；本机验证仍为 6.11.1，源码最低支持版本后续经真实编译门禁统一为 6.10.3。
5. `actions/checkout@v4` 产生 Node 20 运行时告警。checkout 与 Qt 安装 Action 现均固定完整提交哈希，checkout 升级到 v6 提交。

## 证据边界

官方 Qt 元数据探测的 URL、HTTP 状态、字节数、SHA-256 和包名记录在 `qt-ci-availability.json`。本地修复门禁通过不等于远程通过；新的 GitHub Actions 运行尚未产生。
