# MS-02 实施记录

日期：2026-07-23
里程碑：MS-02 SignalDSP 与 SignalCompute 后端
基线：BL1.0（`docs/baseline/Signal-Studio-Dev-Docs`，只读快照）
权威依据：`API-COMPUTE-001`~`003`、`API-DSP-001`~`005`、ADR-006、ADR-009

## 1. 目标

实现 SignalDSP 与 SignalCompute 生产契约，交付窗函数、FFT、PSD、STFT、统计、IQ 度量、滤波、重采样与 CPU/CUDA 后端能力，遵守 ADR-006（oneMKL 默认 CPU、cuFFT 可选、自研 FFT 禁止、Eigen 不出公共 API）与 ADR-009（后端自动选择与显式降级）。

## 2. 交付内容

### 2.1 SignalCompute（`include/signal_studio/compute/backend.hpp`、`src/platform/compute/backend.cpp`）

- `IComputeBackend` 抽象 + `CpuComputeBackend`（始终可用，报告 SIMD/核数）+ `make_cuda_compute_backend()`（经 `cudaGetDeviceCount`/`cudaGetDeviceProperties`/`cudaRuntimeGetVersion` 探测，无设备时返回 `unavailable`）。
- `IBufferPool` + `BoundedBufferPool`：受字节预算约束，超预算/耗尽返回 `unavailable` 而非 OOM；`BufferHandle` 持有主机或设备内存（设备内存经 `cudaMalloc`/`cudaFree`）。
- `IBackendSelector` + `AutoBackendSelector`：CUDA 友好且非 IO 的 DSP 工作负载优先 CUDA，否则 CPU；`requires_gpu` 无 CUDA 时返回失败（显式降级）。每次选择返回 `BackendProvenance`。
- `BackendProvenance` 记录 device/backend_id/runtime_version/device_name，供结果缓存键与审计。

### 2.2 SignalDSP-非FFT（CPU，无 FFT 依赖）

- `windows.hpp`：`WindowType`（rectangular/hann/hamming/blackman/blackman-harris/flattop）、`generate_window`（对称或周期 DFT-even）、`window_coherent_gain`、`window_enbw_bins`。
- `statistics.hpp`：`compute_real_stats`（mean/variance/rms/peak/peak_index/min/max/dc）、`compute_complex_stats`（幅度 mean/rms/peak、相位均值、DC 实/虚、幅度 AC rms）。
- `filter.hpp`：`FirFilter::design`（窗 sinc 法，低通/高通/带通/带阻经谱反转/求和统一设计）、`process`（跨块 `FilterState` 延迟线）、`reset`。
- `resample.hpp`：`PolyphaseResampler`（L/M 有理比，抗混叠窗 sinc 低通截止 min(fs_in,fs_out)/2、增益 L、L 相多相分解、零初始状态）。

### 2.3 SignalDSP-FFT（适配器，API-DSP-001）

- `fft.hpp`：`IFftBackend` 抽象（`create_plan(FftSpec)`）、`FftPlan`、`FftResult`（bins+provenance）、`make_fft_backend(device)` 工厂、`fft`/`ifft` 便捷函数（逆变换 1/N 缩放）、`fft_backend_available`。
- cuFFT 后端（`src/platform/dsp/fft.cpp`，`SIGNAL_STUDIO_HAVE_CUDA` 条件编译）：`CudaFftPlan` 持 `cufftHandle`（`CUFFT_Z2Z`）与设备缓冲，`execute` 经 `cudaMemcpy` H2D、`cufftExecZ2Z`、`cudaDeviceSynchronize`、`cudaMemcpy` D2H；`CudaFftBackend` 经 `make_cuda_compute_backend` 探测后构造。
- CPU FFT 后端：oneMKL 未安装，`make_fft_backend(cpu)` 返回 `unavailable`（环境偏差，不伪造）。

### 2.4 PSD/STFT（使用 IFftBackend）

- `spectrum.hpp`：`WelchPsdEstimator`（分帧+窗+FFT+|X|²平均+密度/谱缩放+单/双边折叠+V²/Hz+ENBW_hz）、`to_db_hz`。
- `stft.hpp`：`StftProcessor`（分帧+窗+FFT+幅度/功率瓦片矩阵+时间/频率轴）。
- 二者注入 `IFftBackend`，结果记录后端 provenance。

### 2.5 公共 API 隔离

公共头仅暴露平台值类型与 `core::Result<T>`；cuFFT/cudart/CUDA 类型不进入签名。`Result<T>` 增加 `operator*`/`operator->`（`std::optional`/`std::expected` 语义，向后兼容 MS-01）。

## 4. 架构与依赖变化

- 依赖 DAG 不变（Core->∅、Compute->Core、Data->Core、TaskRuntime->Compute+Core、DSP->Data+Compute+Core）。`signal_studio_verify_dependency_graph` 仍通过：cuFFT/cudart 以 PRIVATE 链接，在 `INTERFACE_LINK_LIBRARIES` 中表现为 `$<LINK_ONLY:>`，被校验器过滤。
- CUDA 经 `find_package(CUDAToolkit)` 在 `SIGNAL_STUDIO_CUDA_MODE != OFF` 且 `nvcc` 可用时启用；`SIGNAL_STUDIO_CUDA_AVAILABLE` 控制 cuFFT 后端编译与 CUDA 测试注册。
- 无 Qt 类型进入 DSP/Compute 公共头；无新增第三方依赖（cuFFT 随 CUDA 工具链）。

## 6. 已知问题与边界

- oneMKL CPU FFT 后端未安装（vcpkg manifest 模式会源码编译 Qt 冲突；单独 intel-mkl 端口未完成）。CPU FFT 适配器接口就绪但实现返回 `unavailable`，不伪造。安装命令与偏差见完成报告。
- cuFFT GPU FFT 后端已实现并通过解析信号验证。
- 滤波/重采样为标准成熟 DSP 实现（非 FFT/矩阵），黄金值来自解析信号。
- CUDA 不自动安装。
