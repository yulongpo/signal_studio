- WAV：批准录制以有界窗口进入 Data→DSP→Cache 集成。
- SC16：用户指定 `x310_capture_cf1425MHz_sr50MSps_20260521_144220.sc16`，4,004,031,888 字节，SHA-256 `74d0ace877568a1c26505c773f249a02e411546254e67c63c4613bb508f2d605`。配置期实际核对文件大小和哈希。
- 完整索引：生产 `build_full_sc16_index()` 以 64 MiB 块覆盖 1,001,007,972 复帧和 955 个索引 bin。
- 逻辑大文件：相同真实文件通过有界重复映射表示精确的 100,000,000,000 字节；没有创建、扫描或声称测试物理 100 GB 文件。

## 性能样本

Release 当前主机证据：

- 4,096 点 oneMKL FFT：30 个独立样本，P95 30.4 微秒。
- 最终规范全量运行中，剔除全字节 CPU 校验后的真实 X310 纯同盘顺序读取慢侧吞吐：约 393,243,000 B/s。
- 真实 X310 完整生产索引慢侧吞吐：约 286,009,000 B/s。
- 索引/顺序吞吐比：0.727307，要求不低于 0.60。
- 最终 Debug 全量运行的标准三图持续浏览进程峰值：8 GB 与 100 GB 逻辑空间均为 18,382,848 字节，增长 0 字节。每轮跨越 48 个远距离视窗并读取 Windows `PeakWorkingSetSize`，覆盖 `build_frame()` 内部临时读取、PSD 与 STFT 缓冲区的生命周期。

Google Benchmark 的 FFT、STFT、重采样和 GPU 算法矩阵使用 30 个独立样本；真实全文件索引在 Release 使用 3 个独立样本，Debug 使用 1 次结构运行。缓存恢复、三图冷热结果、采样概览、后台共享 FFT、同盘读取和全文件索引均使用产品实现，不包含空循环、睡眠或测试内替代索引。基准程序跟踪 `SkipWithError` 并返回非零；本机只有一块 CUDA 设备，因此多设备切换基准诚实记录环境跳过，其他 GPU 传输、cuFFT、stream 和 OOM 恢复均实机通过。

## 安装与闭包

UI 和无 Qt 安装消费者在 CPU Debug、CPU Release 和 CUDA Release 路径均为 2/2。无 Qt 嵌套构建已显式继承当前 MSVC、Windows SDK、`VCToolsRedistDir` 和 UCRT 环境，普通 CTest 子进程不再因缺失 `LIB` 或运行库目录误失败。CPU Release 与 CUDA Release 分别执行洁净 PATH 闭包：CPU 暂存树不含 CUDA DLL；CUDA 暂存树强制包含 `cudart64_12.dll` 和 `cufft64_11.dll`。两者均包含 SignalStudioCompute/DSP、匹配 VC143、oneMKL sequential 分派和 `samplerate.dll`，`FR-DSP-101` 通过，且不含 SYCL、BLACS、ScaLAPACK、TBB/Intel 线程层或 OpenMP。

整改后独立复审未发现剩余 Critical/Important。该结论同时覆盖纯读取基线、峰值内存测量、冷热视窗真实性、逻辑重复/EOF 边界和默认 Qt 平台启动回归。

Qt 平台插件专项修复后，Debug 测试目录随目标部署 `qwindowsd.dll` 与 `qoffscreend.dll`。自动化 `performance.qt.default-platform-plugin` 清空 `QT_QPA_PLATFORM`、`QT_PLUGIN_PATH`、`QT_QPA_PLATFORM_PLUGIN_PATH` 后验证 `QApplication` 由 Windows 平台初始化并通过；CTest 的 3 项实际绘制测试也全部通过，不再出现“no Qt platform plugin could be initialized”。
