# MS-4.5 工程迁移说明

## 1. 新工程格式

MS-4.5 不提升 Core 工作区主 schema，也不修改批准基线。分析设置作为版本化扩展字段
保存在现有 `.signal-workspace` 中，因此 MS-00～MS-04 的工程、数据源和 Artifact
主结构保持兼容。

保存时写入当前 DSP 参数、显示参数、用户预设和活动参数哈希。结果 Artifact 继续保存
源工程、数据源版本、Selection、Channel、任务和算法，同时把真实分析参数哈希写入
`parameter_version`/provenance；参数变化后旧结果保持可读但标记为过期，不会被新结果
静默覆盖。

## 2. 旧工程迁移

打开没有 MS-4.5 扩展字段的旧工程时：

1. 保留全部既有工程对象和资源链接；
2. 按当前真实已读范围生成“平衡分析”的有界兼容默认值；
3. 使用实/复信号事实选择单边或移位双边谱；
4. 中心频率存在时选择绝对频率参考，否则使用基带；
5. 写入内存中的 `signal.analysis-settings/1.0` 快照；
6. 用户下次保存时再持久化扩展字段，不修改源录制。

该迁移不把 MS-04 的 `psd-default-v1` 伪装成新参数哈希。旧 Artifact 保持原来源文本，
与新参数哈希不相等时明确过期。

## 3. 兼容和拒绝策略

- 同主版本新增的未知可选字段安全忽略；
- 参数 schema 未来主版本明确拒绝，并保留上一有效工程状态；
- 损坏参数文本不覆盖已加载工程；
- 用户预设逐项解析，损坏项诊断并跳过，不影响其他预设；
- 显示参数损坏时回到显示默认值，不改变 DSP 参数；
- 工程保存仍使用临时文件和原子替换。

## 4. 回退边界

旧版本应用可以忽略扩展字段，但不会理解新 Artifact 的参数哈希。若需回退，只能在
保留备份的前提下用旧版本打开；不得把新结果降级标记为旧默认结果。本里程碑不执行
跨主版本降级写回。

## 5. 自动验证

`APP-MS45-PROJECT-PERSISTENCE-MIGRATION` 覆盖新工程关闭/重开、DSP/显示参数和用户
预设恢复、无扩展字段旧工程迁移、未来主版本拒绝和源资源保持不变。
`APP-MS45-ARTIFACT-PROVENANCE` 覆盖真实参数哈希、算法版本、后端/设备、源范围、
工程/源/Selection/Channel/Task 来源以及参数变化后的过期判定。
