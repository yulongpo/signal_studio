# MS-04 实施记录

## 1. 范围与基线

本里程碑只实现 Signal Studio 基础应用及其直接需求，不进入 MS-05。实施前完整读取
不可变 BL1.0、全开发任务、外部测试数据和 MS-03 收口材料。直接需求范围为：

- `FR-INS-001`～`FR-INS-007`；
- `FR-EXP-001`～`FR-EXP-009`；
- `NFR-REL-001`～`NFR-REL-004`。

批准资料未提供 D4；按用户指令不创建物理 100 GB 文件，不执行 Ubuntu 24.04，不自动
安装 CUDA、cuDNN 或其他 NVIDIA 组件。CUDA 验证使用本机 12.4 Toolkit。

## 2. 应用与平台实现

### 2.1 应用编排

新增 `SignalStudioApplicationCore` 与 `SignalStudio.exe`。`ApplicationController`
编排工程、最近工程、只读资源链接、TaskRuntime、Data、DSP/Compute、Visualization、
Inspector 和 ArtifactStore，Qt 不进入应用核心或平台公共头。

工程闭环包含新建、打开、保存、关闭和恢复。导入闭环包含 RAW/IQ、SC16、PCM WAV、
文件名提示显式确认、有界预览、分块读取、暂停、继续、取消和完整帧前缀。分析闭环
使用实际样本生成时域、PSD、STFT 与 Inspector 状态，再提交来源可追溯测量结果。

`--self-test` 在构造 `QApplication` 前执行真实工程、导入、DSP 和结果闭环；该路径
同时用于构建树、安装树和无界面诊断，不依赖 Qt 平台插件。

### 2.2 结果包

Core 新增 `ArtifactDescriptor`、`ArtifactProvenance`、`ArtifactRecord`、
`ArtifactFilter`、`IArtifactStore` 与生产 `ArtifactStore`。每项结果包包含：

- 载荷；
- `manifest.json`；
- `.artifact-index`；
- SHA-256；
- 工程、数据源版本、Selection、Channel、任务、算法和参数版本。

提交使用同目录暂存和原子重命名，已存在结果 ID 明确失败。恢复会清理中断的暂存目录；
查询和导出前重新校验载荷摘要。实现 CSV、JSON、PNG、RAW、WAV、插件声明格式以及
批量导出清单，不把失败半成品登记为成功。

### 2.3 Inspector

Workbench 新增 Inspector 公共状态模型：

- 时域、频谱、STFT、星座、眼图、幅度/相位直方图和瞬时频率适用性；
- 星座抽样上限、密度、参考网格和校正前后对比；
- 眼图符号率与同步来源；
- 视图范围、单位和预处理；
- 通道版本、参数版本和结果过期；
- 独立通道持久化和缺失插件布局降级。

Workbench 页面接口支持宿主安装 P01/P03/P05、切换 P01/P02/P03/P05 及刷新统一内容。
新增虚函数追加在既有虚表末端；析构时先解除中心工作区的 Qt 所有权，再销毁工作台，
修复旧消费者对象仍使用原虚表槽位时的访问冲突。

## 3. Qt UI

生产构建新增五个 Designer 文件：

- `SignalStudioProjectHome.ui`；
- `SignalImportWizard.ui`；
- `SignalLoadProgressDialog.ui`；
- `SignalInspectorPage.ui`；
- `SignalResultCenterPage.ui`。

W01 使用双列布局同时呈现文件/格式和采样/范围信息，文件名提示只有勾选确认后才启动
有界预览或导入。W05 显示文件、路径、大小、格式、采样率、任务进度和取消语义。
P02/P03 绑定真实图谱，P05 以分类、结果列表、来源详情三栏绑定真实 Artifact 索引。
工作台默认显示左侧 Navigator、右侧 Inspector 和底部任务中心；关闭 Inspector 后才
显示右侧恢复入口，与批准原型的主结构一致。

页面截图使用逻辑窗口尺寸和 Qt DPR。顶层 W01/W05 不再只抓取对话框，而是将主窗口、
背景遮罩和工作流窗口合成为完整页面。最终视觉证据使用 Windows 平台隐藏窗口绘制，
先探测本机原生 DPR，再归一化到目标 DPR，既避免桌面工作区裁剪超大窗口，又保留
Windows 中文字体渲染。截图与并排对比脚本覆盖 P01、W01、W05、P02、P03、P05
以及 1280×720、1080P、4K、150% 和 200% DPI。

退出路径显式在成员析构前销毁顶层 W01/W05 对话框，避免主窗口 QObject 子树最后清理
时触发回调访问已经析构的 Ui 包装器；Debug 与 Release 截图进程均以退出码 0 结束。

## 4. 构建、调试与安装

VS Code 默认 F5 改为 CPU Debug `SignalStudio.exe`，构建任务支持明确目标并带入构建树
Qt 插件路径。验证脚本检查目标、预设、生成器、CPU 模式和输入新鲜度。

安装目标增加最终应用。安装消费者在独立前缀消费十个公共模块，启动已安装演示程序，
再运行已安装 Signal Studio 的 Qt 前自检和默认 Windows 平台冒烟。自检暂存目录使用
短路径，避免传统 Windows 路径长度限制；正式安装树不含 Debug nonredist。

## 5. 测试与证据

新增 25 项应用核心测试和 13 项 Qt/UI 回归，共 38 项 `ms-04` 标签测试。CPU
Debug/Release 全量均为 243/243，CUDA Debug/Release 的 MS-04 + Compute 集合均为
50/50，CPU Debug/Release 安装消费者均为 1/1。

外部数据测试实际读取三份批准录制的有界范围，不修改源文件。稳定性短回归包含 100 次
工程生命周期、权限/等价满盘/损坏暂存故障注入和 SHA-256 篡改；8 小时混合操作使用
隔离运行时单独执行，最终结果写入测试与验收报告。
