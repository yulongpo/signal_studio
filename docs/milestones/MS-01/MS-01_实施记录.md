## 1. 目标

在 MS-00 已验收的十模块平台骨架上，交付可独立安装与消费的 SignalCore、SignalData、SignalTaskRuntime 生产契约，覆盖 54 项批准需求：工程与当前上下文 `FR-PRJ-001`~`FR-PRJ-010`、数据导入与读取 `FR-DAT-001`~`FR-DAT-019`、索引与缓存 `FR-IDX-001`~`FR-IDX-012`、任务运行时 `FR-TSK-001`~`FR-TSK-010`、平台能力 `FR-CORE-101`、`FR-DATA-101`、`FR-TASK-101`。里程碑不实现 Qt 页面、完整 DSP 算法库或应用品牌逻辑。

## 2. 实施切片与交付内容

### 2.1 SignalCore（`include/signal_studio/core/`、`src/platform/core/`）

- `result.hpp`：统一 `core::Result<T>` 与 `Result<void>`。`Result<T>` 以 `std::variant<T, Status>` 持有值或失败状态；构造期拒绝把成功 `Status` 当作失败结果，强制调用方区分成功与失败路径。`ok()`/`value()`/`error()` 提供显式访问，避免静默吞错。
- `services.hpp` / `services.cpp`：核心服务入口与能力注册，延续 MS-00 的 `ModuleDescriptor`、`Capability`、`Version`、`Status`/`Error` 不变量。
- 公共头不依赖 Qt 或任何第三方类型；Core 仅依赖标准库与自身。

### 2.2 SignalData（`include/signal_studio/data/`、`src/platform/data/`）

- `signal.hpp`：`SampleRange`（半开 64 位区间，构造期拒绝 `end<begin` 与溢出）、`ComplexSample`、`SignalDescriptor`（标量类型/布局/字节序/采样率/中心频率/缩放/来源溯源）、`SignalBuffer`/`SignalSlice`（实数 `double` 或复数容器，零拷贝切片）、`IDataSource::read(ReadRequest)`、`FileDataSource`（RAW/WAV）、`select_samples`/`export_selection` 选区导出闭环、`IFormatAdapter`/`FormatAdapterRegistry` 标准描述符适配。
- `raw.cpp`：全部批准 RAW 标量（int8/uint8/int16/uint16/int24_packed/int32/float32/float64）、交叠/平面布局、IQ/QI 顺序、大小端、字节偏移、缩放与加性偏移解析。
- `io.cpp`：分块/有界读取，外部 WAV 与 SC16 仅以有界窗口读取，外部大文件不写入仓库。
- `loading.cpp`：加载流程与参数校验、来源字段溯源（`FieldOrigin`）、`DataFacts` 计算。
- `preview.cpp`：有界预览，明确标识为限定长度结果，不冒充全文件 PSD。
- `index.hpp` / `index.cpp`：多分辨率索引缓存键、内存/磁盘 LRU、锁定、损坏恢复与诊断。
- WAV 头解析与文件名参数提示（中心频率/采样率）按 `FR-DAT` 范围实现。

### 2.3 SignalTaskRuntime（`include/signal_studio/task_runtime/`、`src/platform/task_runtime/`）

- `task_runtime.hpp`：`TaskRuntime : ITaskService` 完整实现——有界资源池（`ResourceBudget`/`ResourceProfile`，CPU/IO/GPU/线程单位）、优先级（background/foreground/interactive）、DAG 依赖（`TaskSpec::dependencies`）、暂停/恢复/取消（`TaskState` 状态机：queued/running/paused/canceling/canceled/completed/failed/dependency_failed/stale）、进度上报、超时、重试（`max_attempts`）、幂等（`idempotency_key`）、视图请求与过期（`ViewRequestId`/`try_begin_view_commit`/`stale`）、结构化失败（`FailureInfo` 含 error_code/retryable/suggested_action）、来源过滤（`find_by_provenance`）、历史与制品崩溃恢复（`CommittedArtifact` 原子提交、`history_healthy`）、观察者（`ITaskObserver`）。
- `TaskContext`：任务内取消检查、检查点、进度、原子制品提交。
- 后台任务不引入 Qt，也不触碰 `QWidget`；耗时数据读取由 TaskRuntime 的唯一任务状态源驱动。

### 2.4 集成

数据模块仅依赖 Core；TaskRuntime 依赖 Compute 与 Core；DSP/Visualization 等保持 MS-00 骨架，依赖 DAG 不变。UI 与无 Qt 安装树消费者均编译、链接并调用 MS-01 公共 API。

## 4. 架构与依赖变化

- 依赖 DAG 不变：Core→∅、Compute→Core、Data→Core、TaskRuntime→Compute+Core、DSP→Data+Compute+Core。校验器 `signal_studio_verify_dependency_graph` 仍强制精确匹配。
- 公共头无 Qt/第三方类型；Qt 仍私有于 Visualization/Workbench。
- 无新增第三方依赖。oneMKL/Eigen/FFTW 等仍为后续 MS-02 候选，本里程碑未引入。

## 6. 已知问题与边界

- CUDA 不自动安装；GPU 数值实现属于后续 MS-02。本里程碑 `SIGNAL_STUDIO_CUDA_MODE` 在无界面/UI 预设中保持 AUTO/OFF，不影响 Core/Data/TaskRuntime。
- MAT、NPY/NPZ 与厂商格式通过标准描述符适配接口接入，未伪造未安装第三方解析器。
- 预览频谱明确标识为限定长度结果，不冒充全文件 PSD。
- Signal Studio Qt 应用与 Designer 页面自 MS-03/MS-04 开始实现，本里程碑不提前声明 UI 完成。
- 本机环境与 MS-00 记录的差异：当前主机已安装 CUDA 12.4（`nvcc` 可用），将在 MS-02 启用 GPU 验证。
