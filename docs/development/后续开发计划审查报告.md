日期：2026-08-11

依据：BL1.0 不可变基线、`CODEX_FULL_DEVELOPMENT_TASK.md`、当前分支源码/测试/证据

## 1. 结论

后续开发顺序仍保持 MS-05 → MS-06 → MS-07 → MS-08 → MS-09，但原计划需要实质调整。
主要原因不是已完成代码失效，而是后续范围存在漏项和错配。修订后的详细步骤已写入
`docs/superpowers/plans/2026-07-22-signal-studio-full-development.md`。

本次只校准计划和文档，没有进入 MS-05 功能开发。

## 3. 发现的问题与修正

### 3.1 MS-05 边界过宽

原计划把 P03～P07 和调制/统计实现整体放入 MS-05，混入了 MS-06 的算法、插件和模型
职责。修正后 MS-05 专注 Selection、AnalysisChannel、既有 DSP 处理链、P02/P03 联动、
Inspector、任务/结果来源和 AT-05/14/23；P04/P05 只做通道集成，P06 与模型算法留给
MS-06。

### 3.2 MS-06 漏掉批准需求

BL1.0 把 19 项需求分配给 MS-06，原计划没有完整覆盖 FR-ALG-001～009、插件启停/隔离/
安全模式/信任可见、Dataset 的 WebDataset/查询/缓存/分片，以及多宿主契约。修正后按
依赖闭包、PluginSDK、ModelRuntime/算法、Dataset、宿主集成五个内部门禁推进。

### 3.3 MS-07 不能只做工程打包

MS-07 还有 19 项日志、设置、诊断、安全和可维护性需求。修正后先完成这些产品能力，
再执行质量门禁、安装/便携打包、SBOM/许可证和 198 项需求追踪闭环。

### 3.4 MS-08 宿主选型与基线不一致

批准里程碑明确要求 Signal Generator 薄壳和多应用并存，原计划写成 Signal Review。
修正后改为 Signal Generator 桌面薄壳加 Headless CLI，并强制只消费安装后的公共包。

## 4. 修订后的执行顺序

1. MS-05：Selection 到窄带通道的真实联动闭环。
2. MS-06：依赖闭包 → PluginSDK → ModelRuntime/算法 → Dataset → 多宿主/Python/UI。
3. MS-07：日志/设置/安全 → 质量门禁 → 安装、便携、SBOM、文档和追踪。
4. MS-08：Signal Generator 薄壳与 Headless CLI 复用证明。
5. MS-09：全量最终验收，并按总任务发布 `1.0.0` / `v1.0.0`。

每个里程碑仍执行“修改 → 编译 → 测试 → 证据 → 复审 → 提交”，不执行 Ubuntu 24.04
无界面测试，不创建物理 100 GB 文件；CUDA 适配本机 12.4，cuDNN 只在 MS-06 选定的
ONNX Runtime CUDA 提供程序官方要求时安装。

本报告只分析当前分支。其他分支的实现、提交、报告、标签和完成状态均不构成本次判断
依据，也不影响上述里程碑范围和版本计划。
