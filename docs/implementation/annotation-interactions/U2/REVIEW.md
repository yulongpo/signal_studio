# U2 独立复审

基线为 U1 `3384e17`。规格代理 `u2_spec_review` 和质量代理
`u2_quality_review` 只读检查源码差异，不代替运行验证。

规格复审首轮发现并要求修复四项边界：实际鼠标按下至松开期间树重建
替换按钮、取消按钮误提交草稿、编辑第二段误清除第一段确认，以及
文件菜单和模态取消误提交主窗口草稿。修复后静态结论为 SPEC_PASS。

质量复审提出两项 Important：统一删除未清理按标记统计 PSD 的状态，
可能阻止工程保存；恢复原始范围会覆盖未改兄弟段的确认。已在共享
选择收尾归一化 PSD 状态，并在恢复时保留几何未变段的完整状态。
回归覆盖删除后保存、撤销再定位后保存，以及恢复第二段时第一段不变。

运行中发现未知时间拖拽草稿被同步刷新清空，已改为独立的
`Gesture::draft`；释放前不修改业务范围，未知时间继续只修改频率。
新增回归强制在按下、移动与松开之间刷新。发布前后证据指针基线、
合成夹具文本哈希及模态失败处理也已修正，没有放宽生产校验。

r3 的规格和质量复审分别给出 **SPEC_PASS**、**QUALITY_PASS**，
两项 Important 均关闭。最终运行结果、失败记录及原生证据边界见
[验证记录](VALIDATION.md)。

质量代理另行读取原生 r3 报告及 05、07、10 场景图，确认 **10/10**
及指定显示器/DPI 条件成立，未知时间、删除计数和重开状态符合 U0
在 U2 的要求。真实 IQ/标签、合成交互标记及未验证 DDC 的边界明确，
原生证据复审为 **QUALITY_PASS**。

首次全量 UI 发现旧用例期待拖动途中修改已提交范围。仅更新
`fileSwitchCancelsUnfinishedEdit`，通过控制点的实际像素位移证明预览，
并检查切文件取消不会增加修订、撤销或导航历史。两位代理再次只读
复审，均给出 PASS；未读取私有草稿或新增生产诊断接口，未放宽验证。
