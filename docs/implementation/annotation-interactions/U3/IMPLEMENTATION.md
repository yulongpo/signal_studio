# U3 通道与持久化

基线为 U2 `f2ec417`；继续在 `rebuild/a143-native`，不读取其它开发
分支。依据用户批准的 U0，实现可选质量、统一通道入口、
LocatedSegment / UserRange，以及原生 v6 兼容与升级备份。

质量用于筛选、导出、复查和进度，不作为编辑或创建通道的门槛。
创建时分别保存绑定几何及实际提取范围，裁剪不会立刻产生虚假的
范围变化；名称、备注、质量和无关兄弟段的改变不使通道失效。
未知时间对象的人工范围不写回算法活动段或原始证据。

UI 保留 U0 的 ms 时间输入及既有 DSP 参数表单，提供明确的来源、
范围、可用前缀和字段诊断。没有可读样本也可以打开配置；仅显式
使用前缀才扩大提取范围。多选必须在表单明确指定一个来源。

v1–v5 继续加载，v6 保存首次升级前的原始工程字节，再原子发布。
备份文件名带原版本和原始字节 SHA-256；不覆盖不同内容的备份。
原有通道按创建时快照迁移，不重新计算。

用户已明确更换外接显示器；当前实际探针为 U27U2D、连接序号 1、
DISPLAY2，3840×2160、150% DPI。验收定位唯一实际 4K/150% 屏，
不沿用旧屏名称、设备路径或连接序号；历史证据保持原样。

继续使用既有构建、CTest、截图和 CPU DDC。用户将代表性数据移到
`resources/sigmf_data_demo/`；IQ 及 meta 的 SHA-256 与旧 W: 样本相同。
新原生场景采用此本机小型实际 SigMF IQ，手动/算法标记仍明确为
UI 夹具；模型效果与交互/DDC 分开。用户提供的原始样本不自动加入
本节点源码提交。

冻结 U2 v5 工程仍引用原 W: 数据。兼容检查通过真实 ProjectStore
读写其原始内容，核对逐字节备份及旧通道快照；不重写旧来源，不以
新本机样本冒充旧通道执行。新建 v6 工程另行验证真实 IQ/DDC 和重开。
原生 Partial 界面场景为完整物理文件上的受控可用前缀，明确记录该
边界，不将它声明为停止实际载入所得的 Partial 证据。
本节点完成自检、复审及本地提交后才进入 U4 的最终综合交付。
