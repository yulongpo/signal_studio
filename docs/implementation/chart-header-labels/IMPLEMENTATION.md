# 谱图切换与参数标识修正

本轮依据用户确认的《谱图切换与参数标识统一修正》实施，基线为 `rebuild/a143-native` 的 `55af26330bbf36e1562b9b2669a9965693b6d9b1`。保留此前未跟踪输入和历史报告。仅支持当前 v6 工程，没有新增测试用例或捕获场景。

## 实现

- 宽带“时域波形 / 功率谱 / 检测证据”和“时频图 / 瀑布图”保留在图名之后的左侧分段组，独立于右侧参数条。
- 共用 `ChartControlStrip` 为参数显示可见短标签；有明确文字的按钮、复选框不重复标签。标签、控件一起计算宽度和进入平铺更多层，编辑器和业务绑定均复用。标签对象名为原控件名加 `Label`。
- 控件按保留优先级稳定排列，宽窄带以及窄带各页切换后顺序一致。标题栏保持单行，组合框按实际内容和字体分配宽度；空间不足先隐藏辅助摘要，再收纳低优先级字段。
- 设置层打开期间只同步条件可见性。字段编辑或下拉展开期间延后重新分配；普通刷新不重建编辑器、不清除草稿。
- 参考电平、动态范围平时显示两位小数和完整单位。需要额外精度时，进入编辑器显示可往返还原的完整值；仅聚焦不改变原参数。预设从数值数据读取，自定义编辑沿既有提交路径校验，存储和计算不使用舍入文本。
- 清除重复动态范围摘要、窄带 N 的重复 PSD/STFT 前缀及迁移眼图编辑器后遗留的空“眼图”标签。眼图设置使用“分量、周期、轨迹”，不显示内部对象名。

## 既有检查迁移

默认数值文案断言改为两位小数，预设选择按数值查找。旧 `rangeTag` 的布局断言改为检查实际 `dynamicLabel`。保留原断言、滚轮保护、参数提交和控件命中意图，没有增加测试场景。

最终19个相关UI用例还发现旧的单小数提交文案，以及窄带频率字段/滚轮遍历假定字段始终位于标题栏的问题；现有 `revealParameter` 按实际归属图谱打开可见的更多设置，再滚动到同一个原编辑器。该迁移不切换到隐藏页面、不绕过不可见入口，也不新增用例。

继续定位四页往返问题发现，进入更多层的窄带字段已迁到主窗口宿主，后续仍从窄带工作区局部查找，导致频率、网格或N编辑器漏绑，仍归属于隐藏的旧页面。改为从稳定的主窗口查找同一个编辑器。同时监听实际页面栈的 `currentChanged`，由窄带工作区发出 `pageChanged`，覆盖页签、演示跳转和恢复等入口；同页刷新不重复迁移控件。临时诊断日志/离屏截图保留在任务目录，诊断代码已移除。

补充修正后，两配置现有相关UI均21/21通过（19个业务用例），四组UX CTest均4/4通过（Qt27项、业务19项）。最终UI耗时Debug247.865秒、Release75.376秒；两配置此次离屏回归并行执行，这些时长不作为隔离性能基准。未新增测试场景，未运行综合UI全106业务用例或全部29个CTest目标。

实际长小数截图中还发现右侧摘要将参考和动态混写为两个数值；现分别显示“参考”及源数据对应的功率单位、“动态”及dB，精度与标题栏一致。该文案修正完成两配置构建，并另用最终原生截图确认。

Debug交付重建后曾在生成原生报告之前发生 `0xc0000005`。本地调试调用栈定位于 `__scrt_common_main_seh` / CRT `exe_common.inl:253`，尚未进入应用 `main()`。同一源码使用 `/p:LinkIncremental=false` 完整重链后恢复，原生24场景、两个既有启动/电平用例及独立GPU/软件启动通过；这些证据支持增量链接产物异常的判断。最终Debug GUI可执行文件采用非增量链接，未向应用逻辑加入规避代码。失败日志、调用栈和重链命令均保留。

补充精度展示的首个手工v6输入只改了辅助图类型，没有同步活动Y轴范围，被现有工程校验拒绝；同步对应PSD范围后成功打开。该失败属于验收输入准备，未放松工程校验。

原生捕获首次在第18场景中止。原报告显示 `mainPlot` 的请求/提交代次均为10、质量为 `settled`、worker已空闲，但 `gpuUploadsPending=true`；错误文字“resumed preview”不能据此解释为重新运行 DSP。现有捕获器改为在原等待预算内观察连续80毫秒稳定，与已有窄带等待方式一致，GPU及实际渲染条件没有放宽。UI CTest 的480秒保护不变。
