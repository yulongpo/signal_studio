## 3. UX-R3-02 宽带辅助图/主图轴标题与边距布局（P0）

### 代码事实
- `ui/charts/plot_widget.cpp` 中 `PlotWidget::plotRect()` 对主图和辅助图固定采用左边界 `88` 逻辑像素。
- 宽带辅助区可切换时域/PSD；主图可切换时频/瀑布。X/Y 轴物理含义会改变，现有滚轮缩放/轴拖动必须原样保留。

### 改造任务
- 将 PlotGeometry / AxisLayout 抽离，分别测量 `tickLabelWidth`、`axisTitleWidth/Height`、单位展示与 DPI 下的 `QFontMetricsF`，以实际已格式化的最大刻度值测量，处理科学计数法、负值、Hz/kHz/MHz/GHz、dB/dBm 和不同字体。
- 方案 A：Y 轴单位置于 Y 刻度顶部或图框左上边角，刻度靠近图框；方案 B：完整物理量/单位进入图谱标题栏，图内只保留刻度；方案 C：传统竖排标题作为可选模式。优先 A，原生截图评估后确定默认。
- X 轴 label 与 tick 使用独立垂直预算；时间或频率切换时依据物理轴变更单位，不发生标签遮挡。
- 两图绘图区左边界尽量一致。优先采用共享最大刻度占用以实现轴对齐；若代价过大，允许局部弹性，但须给出实测对比与理由。
- 以当前 88 px 为基准，目标评估 `48–64` 逻辑像素，而不是保证硬性压到某个数；长标签无损显示优先。
- PlotRect/AxisLayout 变化后更新覆盖层、ROI、标记控制点、鼠标命中、光标、轴滚轮、拖动、缩放与 GPU/软件回退的几何映射。

### 验收矩阵
- 时域、PSD、时频、瀑布 × 长短刻度 × 4K 150% × GPU/软件绘制；执行当前已指定的真实屏幕检测逻辑，实际屏幕不存在不能伪称已验收。
- 前/后截图测量左侧利用率、绘图区有效宽度、文字裁剪、光标/框坐标误差；主图和辅助图对齐、Y轴操作区存在。

## 4. UX-R3-03 数据集自动标签发现及导入（P0）

### 已确认的 MATLAB 数据集目录约定

```text
<dataset_root>/
├── data/
│   ├── sample_001.data
│   └── sample_002.data
└── label/
    ├── sample_001.txt
    └── sample_002.txt
```

导入 `data/sample_001.data` 自动尝试 `label/sample_001.txt`；**主名完全一致是默认配对条件**。路径匹配与 TXT 内容解析是两个独立步骤，不能因路径匹配成功就跳过格式校验。


### 现状
- `infrastructure/label_import.cpp` 已实现指定生成器带键 TXT、TorchSig SigMF 及配对 rfbench JSON 的验证导入。
- 目前 TorchSig profile 限制 `cf32_le`、配对文件同目录、固定 capture 等；不得把这些 profile 限制宣传成对任意 SigMF 通用兼容。
- **用户所指 MATLAB 数据集不是 `.mat` 容器**：样本文件为 `data/*.data` 原始二进制，标签文件为相邻 `label/*.txt`，且两者具有相同 basename。必须为其实现独立 `MatlabDataTxtProfile`（暂定名），而不是把 `.mat` 解析作为本轮验收目标。实际 `.data` 编码与 TXT 字段格式仍须从真实样例/数据集文档核实，不得臆测。

### 统一流程
`SourceImport -> DatasetInspector -> LabelCandidateDiscovery -> LabelParser/Profile -> PhysicalCoordinateValidator -> Preview/ConflictResolution -> AnnotationService -> Persist/Version`

#### 发现规则
1. SigMF：先查同目录同 basename `.sigmf-meta` 与 `.sigmf-data`；标准 SigMF 的 `annotations` 有实际记录时进行预览；支持已有 rfbench 同名 JSON 作为补充但须校验一致性。区分“合法空 annotations”与“数据或字段格式错误”。
2. 生成器 TXT：只对识别出的 profile 或高可信文件名执行格式验证；不可将任意同名 TXT 按生成器标签强行导入。
3. MATLAB 数据集：导入 `.../<dataset>/data/<name>.data` 时，优先定位 `.../<dataset>/label/<name>.txt`（严格相同 basename，文件扩展名分别为 `.data` / `.txt`）。若该文件存在，读取并按 MATLAB DATA/TXT 数据集 profile 验证标签字段、样本时频范围及文件身份；验证通过后自动导入统一标记。若对应 TXT 不存在，允许手工标记或用户主动选择其他标签文件，**默认不扫描并猜配其它 TXT**。若同名候选出现大小写冲突、路径别名、重复或解析错误，应显示明确原因并让用户选择/修正，禁止静默匹配。标签可包含类别、时间/样本区间及频率上下界，缺失字段必须明示为未知，不伪造二维框。原始 `.data` 样本编码、字节序、实/复类型、Fs/Fc 仍需从配置/数据集说明取得，不能仅凭 `.data` 扩展名推断。支持从 `label/<name>.txt` 反查 `data/<name>.data`（用于主动导入标签），不得错误匹配另一数据文件。
4. 不在未授权目录全盘递归扫描。默认仅扫描信号所在目录、识别出的同级 `label/` 和明确指定的路径；限制扫描数量、大小、超时及解析深度。匹配关系可由用户确认一次并保存在数据集 profile/工程中，下次复用前仍核对文件身份。
5. 无标签时不弹阻断警告：展示“未发现标签，可手工创建或选择标签文件”；支持拖动绘制/完整范围表单/F2 编辑；来源为 Manual。

#### 物理语义
- 样本区间采用 `[start,end)`、uint64；区分从 0/1 开始的 MATLAB 索引；秒、样本、帧转换须由明确 Fs 决定。
- 支持基带偏移与绝对 RF 频率，Fc 只添加一次；处理频率上下限/中心带宽、超界、NaN、整数溢出、缺失字段；不可静默舍入为貌似正确的精确标签。
- 原始标签、量化精度、来源路径/hash、导入器版本和转换参数可追溯；对时间未知或仅有类别的标签不伪造二维时频框。
- 自动重检对已导入来源做身份比较：相同则不重复导入；变动则提示重载/保留/比对，并保留用户修订。手工标记不可被自动导入覆盖。

### 验收
- 完整 TorchSig SigMF、SigMF 无 annotations、损坏元数据、rfbench 冲突、生成器 TXT、MATLAB `data/<name>.data` + `label/<name>.txt` 同名跨目录配对、大小写冲突/同名异常、无对应 TXT、错误 TXT schema、标签超出数据范围、完全无标签、重新导入去重、移动源文件/标签目录等情景。
- 导入时给出标签数量、类别分布、时间/频率范围、来源与被排除原因；取消不产生部分修改。

## 5. UX-R3-04 窄带页面结构与数据链（P0）

### 页面和职责
1. **信号观察**：时域/PSD/时频、通道基础信息、游标与范围。
2. **星座图**：I/Q 散点、显示抽点/密度、原始/预处理/同步/判决阶段切换、参考决策区域、缩放和坐标读数；不得把合成散点伪称真实。
3. **眼图**：I/Q 分量、UI 周期、轨迹数、定时偏移、滤波/定时对比；符号率未知时清晰提示并允许假设。
4. **调制识别**：传统或深度模型接口、候选调制与分数、方法来源、适用条件；未部署模型显示“不可用”，不能假运行。
5. **解调分析**：手工或经确认的调制假设、判决/同步状态、符号/比特流及证据；真实与演示明确隔离。
6. **同步与参数**：跨页面共享配置面板，不做第五种重复算法执行链；其主要参数可在其它页按需打开。

### 状态架构
- `ChannelAnalysisContext` 保存实际 Fs、数据来源、样本选择、滤波/CFO/符号率/定时/载波恢复配置、数据修订以及分析请求代次。
- `AnalysisStageSnapshot` 将原始 IQ、滤波后、频偏补偿后、匹配滤波后、定时恢复后、判决前后等中间状态以独立可观察结果暴露。阶段仅在真实执行成功后标记完成。
- `ConstellationViewState` 与 `EyeViewState` 保存显示专属参数，避免切换页面触发无关 DSP 重算；绘制密度/颜色改变不重新同步。
- 调制识别是与星座/眼图**并列的消费者**，其候选可以建议修改同步假设但不能隐式覆盖手工设定。最终解调可使用用户确认的候选。
- `domain/project.h` 当前 `NarrowbandPage { Observe, Modulation, DeepLearning, Demodulation }` 必须进行明确的新枚举、工程持久化值迁移/兼容映射；旧 v6 的 Modulation 页面定位到新的默认合理页，不能无故清空分析配置。

### UI
- 顶部页签导航或左侧轻量垂直导航二选一，先出可点击原型并实屏对比；保持通道身份和全局数据源指示常驻。
- 图谱设置位于各自页面的图谱标题栏；共享同步参数和模型选择在可停靠侧板，禁止常驻挤占图谱空间。
- 星座图保持等比例 I/Q 轴，眼图注明 UI 与实际 samples/symbol；提供同步阶段/有效数据范围状态。

### 验收
- 星座与眼图独立页面可完整工作，改变页面不会丢失其独立视图区；共享参数更改正确导致依赖的分析结果失效并重新计算。
- 切换通道、重新打开工程、取消后台计算、切换同步假设及算法不可用均有清晰状态。
- 保留已实现 PSK/QAM/APSK 恢复与真实 IQ，不能为了拆页而退回合成数据。

## 6. UX-R3-05 宽带检测、工程树与结果联动（P1）

- 以 `检测入口 -> 配置/预检 -> 任务运行 -> 结果审查 -> 标记编辑 -> 窄带通道` 形成单一路径；主工具栏、ROI 操作和右侧栏统一配置入口。
- 默认展示模型/范围/少量核心参数，高级参数折叠；保留完整原始请求和运行环境技术详情。
- 状态明确区分 queued/validating/running/cancelling/completed/cancelled/failed/interrupted、真正零结果、未读、排除、覆盖不足；不能将未测区域涂成负例。
- 任务卡优先显示模型、源、阶段、进度及已发布数；百分比有明确定义，不将单一 readFrames 误称总任务完成率。
- 检测结果图层可开关、筛选、定位、批量质量判断；选择不自动缩放，显式定位才移动范围。
- 对检测结果的通道创建应支持直接进入配置、来源快照、有效带宽与复基带采样率约束；默认 2B 目标、1.5/2/4/8 倍率及手工 Fs 遵守既有规则。
- 保持 TensorRT worker 隔离、任务冻结请求、历史不可变性、取消/恢复语义、运行时标注来源。

## 8. 开发和验证硬约束

1. 先读取项目 `AGENTS.md`、README、当前需求/架构/测试、既有冻结协议；不要擅自改动无关领域功能。
2. 新模块采用 domain/application/infrastructure/ui 分层；GUI 不直接实现 MAT 解析、标签算法或同步算法；IO 和耗时运算可取消，GUI 主线程不得阻塞。
3. 优先少量有判别力的测试，复用既有回归脚本，不在每个步骤进行重复 SHA 计算；开始确定基线、阶段提交记录 ID、最终核验 HEAD 即可。
4. 调用 Qt/DSP/GPU/worker 的真实路径验证；测试必须说明合成夹具、真实 IQ 与真实模型推理的区别；不能把 offscreen 渲染当作真实显示器验收。
5. 所有新字段有 schema/version 和默认值；读取失败必须明确诊断，不得 silently drop annotations/channels/runs。
6. 每个 Gate 完成可分阶段本地提交，但在独立子代理最终审查明确通过前，严禁向任何远端分支 push、创建会导致远端更新的合并操作或发布 Release。执行过程中如果远端 HEAD 变化，先比较影响并正常合并/变基，禁止覆盖用户提交；保留所有用户未跟踪文件。
7. 禁止无必要变更输出文件目录与大型依赖；正式二进制包保留完整运行时身份记录及独立运行步骤。
8. 需记录用户实际指定的 Windows 4K/150% 屏幕探针；无法连接实屏时标为 Blocked，不得用模拟窗口假装完成验收。

## 10. 强制独立子代理终审及远端同步门禁（最高优先级）

**本条是最终发布的硬性前置条件，优先于本文任何关于“完成后推送”“统一同步”“交付发布”的一般描述。**

1. **先完成本地实现，再审核，最后才允许同步。** Codex 主代理可自主执行 R3-G0～G7、运行测试、生成文档并逐阶段进行**本地 Git commit**，但审核结果为明确 `APPROVED` 前不得 `git push`、更新远端分支、创建远端标签或发布 Release。不得以“测试通过”“主代理自检通过”“另一个对话模型给出意见”代替正式子代理审核。
2. **必须启动真正独立的代码审核子代理（Review Agent）**，其任务是独立复查主代理交付的最终代码、关键 diff、测试日志、验证证据和任务书。审核子代理不得复用主代理的自我结论，也不得仅凭提交说明、`VALIDATION.md`、截图清单或测试计数判定完成；要读实际代码并核查关键路径。审核子代理与实施者职责隔离；主代理不得替它签署通过。
3. 审查至少覆盖：`.ssproj` 工程创建/保存/迁移/源路径重定位；轴 label、刻度布局与 X/Y 轴操作；MATLAB `data/*.data` ↔ `label/*.txt` 同名匹配、TXT 字段映射、TorchSig/SigMF 自动发现、标签去重与人工标记；独立星座图/眼图和共享同步状态；检测冻结任务、结果覆盖语义、取消恢复、标记/通道关联；Debug/Release 编译测试、真实显示器/独立部署、文件兼容、异常和性能回归。
4. 子代理输出独立审核报告 `docs/implementation/ux-r3/INDEPENDENT_REVIEW.md`，包含审查对象的精确本地 HEAD、抽查源码路径/相关函数、运行或复核的证据、问题级别（Blocker/Major/Minor）、遗留风险及明确的结论 `APPROVED` 或 `REJECTED`。缺失必要证据、关键门禁未通过或发现 Blocker/Major 未解决时必须判定 `REJECTED`，不得使用“有条件通过”绕过门禁。确因设备缺失而不能完成已约定的强制实屏验证时，状态应为 `BLOCKED`，也不得推送，除非用户另行明确书面调整该验收门禁。
5. 审查 `REJECTED` 或 `BLOCKED` 时，主代理先修复/补测，再**重新派发独立子代理审核**。新的审核必须覆盖修改后的最终 HEAD；旧版本 `APPROVED` 不对后续新提交自动生效。最多允许主代理自行持续修复与复审，不得因反复失败自动降低标准。
6. **审核通过后还有一次防竞态检查**：在执行 push 前确认当前本地 HEAD 与独立审核报告中批准的 HEAD 完全一致；检查工作树没有混入未审核的待推送改动；`git fetch` 取得最新远端状态并比较祖先关系。若远端发生变化，安全整合后必须重新跑受影响的回归并重新提交独立子代理审查更新后的最终 HEAD。严禁 `--force`/`--force-with-lease` 覆盖远端历史。
7. 只有全部门禁满足，才允许按任务书批准的目标分支和顺序执行**正常非强制 push**。同步后核验远端 HEAD 与批准版本、记录 commit 链接和同步结果。若审核没有通过或子代理执行能力不可用，**任务只能停在本地待审状态**，清楚报告阻塞，绝对不允许主代理自行替代审查后推送。
8. 独立审核报告及批准版本身份必须随交付被保留，最终 `DELIVERY.md` 清楚列出实施提交、审核者角色、审核状态、证据路径、实际远端同步与否。

**终止条件：** `独立 Review Agent 明确 APPROVED` AND `被批准 HEAD = 实际待推送 HEAD` AND `最新远端分支安全可同步`，三项全部为真才能执行远端同步。任何一项为假或不可验证，一律不推送。
