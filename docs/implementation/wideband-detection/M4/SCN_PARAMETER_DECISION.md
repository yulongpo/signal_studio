# M4 SCN 噪底裕量控件例外：已批准

获批方案 A 保持 M0-P 参数启用矩阵。补审发现，SCN 的 CNR/频率收边固定为 3 dB，sample/ROI 门限分别由带限功率、自适应 ROI 轨迹计算；它们不使用卡片中的可调 dB 裕量。Coarse 与 Fine 的真实粗回退使用固定 6 dB。当前 SCN 的 sample/ROI/None 模式却允许编辑该值，帮助文字也错误宣称参与时间精修。

建议只为 SCN 增加明确的启用矩阵例外：所有时间策略下禁用没有可调作用的噪底裕量控件，显示“SCN CNR/频率收边固定 3 dB；Coarse/粗回退固定 6 dB”。保留卡片布局、字段位置、其它参数、动作和状态流程；FFSCN 参数启用规则保持获批矩阵。保存的用户值仍保留，切换回具有可调作用的 profile 时使用。

这项建议不改变 SCN 数学，不将 dB 裕量接入线性功率门限，不修改 sample/ROI 已批准的算法，也不改变默认数值结果。该例外须用户确认后才应用，不能以修正文案代替确认。

另一个选择是严格保留 SCN 当前启用矩阵，暂将此项参数契约标为未完成；不能让无效控制继续显示为已实现。当前批准范围内没有可直接采用的新 SCN 裕量算法，若要求新增数学作用，需要另行明确其定义并验证。

Fine 回退读取已禁用 Coarse 历史参数的问题不需要改变矩阵：回退有效参数固定为既定 6 dB、minBurst 10 ms、splitGap 20 ms，保留用户 Coarse 存储值供直接 Coarse 分支使用。此项由主实施修复和自检。

决定：2026-10-14 用户明确回复“按建议确认，并继续推进完成任务”，批准建议 A。已应用 SCN 专属禁用和固定 3/6 dB 说明；保留已保存值、FFSCN 矩阵及布局/动作。对应 Qt 回归核对 Sample/ROI/Coarse/历史 None，以及切换 profile 后的用户值保留。等待本轮实际执行与最终原生检查，不把批准当验证通过。

用户随后在对应问答卡明确选择“A：批准 SCN 控件例外，禁用无效裕量并更正说明”。定向 Debug 场景通过，获批三文件 SPEC/QUALITY 通过；合并其它 M4 草稿的隔离 Debug 全套23/23、UI94/94通过。当前冻结执行版本仍未集成证据草稿，最终原生检查待执行。
