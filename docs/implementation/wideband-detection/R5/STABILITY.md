# R5 稳定性修正

前置R4：`949ec38`。仅使用当前分支，产物位于本节点任务目录。最终运行结果和部署身份见`SELF_REVIEW.md`。

## 原子发布

保留`QSaveFile`和`directWriteFallback=false`。open/write失败立即报告；仅commit替换失败，对同一不可变字节用新的QSaveFile最多尝试三次，间隔20/40ms。永久失败保留旧manifest，错误包含操作、相对路径、操作后的Qt原因/错误号和尝试次数；不直接覆盖旧文件，不把失败改成Completed。

受控Windows测试分别保持拒绝替换句柄、在15ms后释放短时读句柄：前者仍明确失败且旧字节不变，后者自动发布新快照并精确重开。这只能证明受控共享冲突的恢复能力。M4历史失败没有记录当时的底层API原因，不能追溯认定当时也由共享锁造成；历史失败记录保持不变。另选原失败文件一次完整流程复验，仍不把一次成功当作历史根因证明。

## 执行批量与模型资源

来源计划先按实际窗口数量、CPU工作集、传输和保存预算降低执行批量，单窗口不再预分配双批。独立worker通过显式启动参数接收执行批量上限，原始请求保持不变。后端按该上限选择优化profile并分配真实工作区；在资源/profile容量或CUDA分配不足时，从2降至1重新初始化，销毁失败候选释放其资源。输入计算网格、真实谱帧和结果几何不缩减。

worker返回`logicalMaximumBatch`、`requestedMaximumBatch`与必要的`batchAdaptationReason`；任务采用实际返回批量。推理在准备/复制前拒绝超过实际分配的批次，避免单批缓冲区被双批写入。

真实模型资源用例先测单/双批所需字节，再把预算设于两者之间，核对请求2、实际1及真实前向成功。当前测得双批分配937723904字节、单批468862976字节，runtime18874368字节；最终具体值以原始运行日志为准。这里验证资源适配，不评价检测精度。

## 反馈与规模

原生启动/取消反馈使用固定运行/取消按钮实际`QEvent::Paint`，同时核对当前可见区域、提交runId、按钮启用状态和任务生命周期。计时等到新状态真实绘制结束；报告明确测量固定按钮状态反馈，不用屏外状态标签的`repaint()`代替。取消完成延迟独立记录，必须保存非空真实模型前缀且`0 < completed < eligible`，重新读取run与可见终态一致。

压力夹具仍为1000对象×100活动段、20次选择/筛选，检查分页和控件数量、首图帧、P50/P95、进程RSS/峰值/私有字节。它是明确标示的合成UI压力，不能作为真实RF或大量数据效果证据。

继续使用项目构建、截图、GPU smoke和独立部署脚本。Debug/Release、GPU显示、软件回退、TensorRT推理分别归档；原生屏幕约束保持连接屏2 Redmi27NU / DISPLAY6、4K/150%全屏。
