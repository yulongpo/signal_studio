# M1 统一标记、原始标签与 WAV

## 实现范围

本节点独立实现统一 `Annotation`，原有 `Mark` API 是兼容别名，活动段投影只供已有视图使用。原始标签、手动标记和算法结果使用相同实体；原始证据不可变，边界与备注修改保存为修订，复核决定绑定修订。接受标记不复制对象。算法来源当前仅支持领域模型及夹具，真实模型与任务链属于后续节点。

统一表按 200 条分页，工程树每来源最多展示 100 条，并保留分页或筛选外的选择。三来源图层分别开关。详情支持活动段切换、精确样本/RF 边界、显式修订、恢复原始值、分段/合段/删段、人工采用观察范围及备注。编辑使用现有参数提交策略；切换文件、段或修订撤销未提交草稿。

新增通道要求已确认、当前可用的活动段，保存不可变的段/修订/来源快照。已有通道参数不会随标记修订、拒绝或软删除改变；界面显示来源关系。普通通道参数编辑不能修改来源绑定或删除快照。有效分析带宽的显示设置不改变原始样本身份，物理频域内的原始标签仍保留。

## 输入边界

仅适配两类原始标签：指定生成器的冒号键值 TXT，以及 TorchSig 指定 SigMF 与同名 rfbench JSON。生成器载波可有多个 TIME 段；SigMF 的 RF 频率直接使用，补充 JSON 的基带频率仅平移一次。补充事件按内容唯一匹配，不按数组顺序配对。整批验证通过才发布，重复来源幂等；JSON 冲突可显式选择只导入 meta，并保留忽略诊断及原文。

WAV 只接受 RIFF、PCM16、双通道 I/Q、四字节样本帧。有界扫描 chunk 元数据后复用本仓库样本 reader，不把 WAV 整体载入内存；支持奇数填充 chunk 和非最后位置的 data chunk，其它 WAV 格式明确拒绝。

## 保存与预算

工程保存为 v5，继续完整读取 v1–v4，旧标记 ID、选择、通道及参数迁移。每文件支持最多 100000 个对象和 100000 个活动段；内容寻址分片最多 4096 条、8 MiB。大段标签原文存独立来源快照，单快照最多 32 MiB；标记与来源快照合计最多 256 MiB。来源索引 v2 保存相对路径、SHA-256、字节数；仍可读取 v1 内嵌来源索引。

先写不可变快照及分片，再原子提交工程清单。加载核对路径、hash、数量、类型、引用和数据边界，完整验证后替换当前状态。无损 annotation JSON 包含原始来源、证据和完整修订；CSV 每活动段一行，导出对话框说明其字段损失。交换 JSON 不作为第三类外部标签适配。

手动命令历史按文件隔离，最多 40 条、128 MiB；批量操作预验证，失败不部分生效。撤销业务修改独立于视图导航历史。
