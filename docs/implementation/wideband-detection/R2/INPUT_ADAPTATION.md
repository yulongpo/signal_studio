# R2 模型输入适配

R1 已自检提交 `5df99ba` 后开始。仅修改当前分支；界面参数提交与来源短窗规划属于后续R3，本节点不将它们宣布完成。

## 分析参数与后端布局

`DetectionRequest.inputAdaptationVersion` 默认为2，JSON请求 `schemaVersion=2`。profile身份和权重版本保持；FFT、hop、窗口/滑动帧数属于该请求的分析配置。读取旧 `schemaVersion=1` 时明确恢复适配版本1，保留原频率布局及原始运行证据，不重算历史结果。

用户补充的结构条件是模型输入频率长度须为2的整数次幂且不小于各自的 `2^down_nums`。FFSCN 当前权重 `down_nums=11`，适配层取不小于分析点数及2048的最小2次幂，在完整物理频带上插值；时间行不扩充。预测按实际模型宽度解码后乘以 `analysisBins/modelBins` 还原到原分析网格。原有65536点默认配置为恒等路径。插值不增加真实频率分辨率。

用户明确所有类型谱均可用于检测，平均谱没有禁用规定。请求的 `spectrumMode` 保存默认、瞬时、平均、最大或最小谱；平均谱在线性功率域积累后转回dB。FFSCN默认保留实际逐帧输入，显式选择统计谱时使用所选统计谱；SCN默认最大保持，显式选择其它谱时使用所选谱。SCN当前固定导出包使用32768点，由适配层在同一物理频率轴上做分段常功率重分箱，再逐窗minmax归一化；该导出规格不是算法必须使用32768点的结论。共同dB参考避免转换溢出；同网格为恒等路径。输出按 `analysisBins/modelBins` 映射，平均谱也可参与检测和辅助分析。

SCN的 `down_nums=11` 由用户在2026-10-15确认，故结构最小长度也是2048；现有32768点engine满足该条件。资产边界与确认来源见 `SCN_CAPABILITY.md`。显式谱模式下，网络输入及SCN的CNR/频率收边共用 `selectDetectionSpectrum`，不能模型用当前谱、后处理却偷换成历史最大谱。

`DetectionModelOutput` 携带实际 `inputBins`、`actualFrames`。worker接收不超过用户窗口帧数的实际时间行；返回原始hm/bw/off。任务解码、分片保存与重开验证均使用实际模型head宽度，不能以用户FFT/4错误解释SCN或对齐后的FFSCN head。

峰的身份继续使用模型网格的唯一 `peakIndex`，只有几何边界映射到分析网格。不能缩放后截断峰ID，否则低点数分析网格会把多个模型峰变成同一个ID并导致跟踪失败。跟踪器与SCN后处理分别记录/接收模型峰数量上限。

## 模型资产与运行

旧v1模型包仍可用于其真实支持的默认张量。新FFSCN v2包声明动态输入范围、频率结构步幅、冻结checkpoint身份及engine hash，模型导出记录见 `DYNAMIC_MODEL.md`。资产保存在本机R2目录，不改M3旧engine。

后端遍历engine实际optimization profiles选择可执行当前张量的一档，按当前形状计算context workspace，独立检查CPU工作集、模型blob、实际空闲显存与设备分配预算。GPU/ABI、数据类型、连续布局、包字节和hash仍必须真实有效；用户分析配置不再与参考FFT/帧数作相等比较。

最大时间×频率范围受本机显存制约；第一次过大的构建失败保留。模型包的资源范围不等于算法只接受默认参数。原生任务不得重复真实行来伪造观察，不得静默换用其它谱类型；实际所选谱、输入规格与适配方式必须可追溯。

## 行为检查

- 非默认9帧合法，错误字节长度/NaN/Inf/预算超限仍失败且保持调用者输出。
- FFSCN短网格与不规则网格插值到满足结构条件的长度，仍只使用实际时间行，结果物理频率映射不变。
- SCN65536→32768验证线性功率积分而非直接平均dB；64→32768验证物理网格展开及真实最大帧来源。
- 存储可往返非默认hop；旧v1参考身份仍按旧规则读取。
- 奇数3001点分析网格经过两类模型的投影仍还原相同Hz；stride=4只约束模型head，不约束分析网格。
- 两模型适配后的raw-head按模型宽度写盘、重开验证；篡改不可变字节必须失败。
- 新engine的5组PyTorch对照与C++原生前向分别执行；默认模型数值回归和SCN等价映射控制单独记录。张量前向不是效果评估。

最终结果、源码/模型hash及节点自检状态在提交前填写到本目录的 `SELF_REVIEW.md`。
