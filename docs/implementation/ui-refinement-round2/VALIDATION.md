## 已保留的失败迭代

- 第一轮Debug全量运行中28个目标通过，综合UI在480.05秒终止。原始Qt日志还包含旧色表固定宽度、旧参数父容器和隐藏页面入口三个断言失败。该次与Release编译存在重叠，不作为隔离的界面性能基准；没有增加480秒保护。
- 条带事件监听已从全应用收窄为所属控件及设置层；旧用例从实际页面/参数宿主进入，移除过期的固定宽度假设。
- 取消旧工程兼容后，首轮Release在sample_format中发现残留v1/v2/v3读取断言，已删除该旧块，72项真实格式/DDC及读取边界检查保留。两个配置的该既有目标随后通过。
- Release综合UI继续发现方法切换时窗函数字段仍显示的问题。原因是打开设置层时跳过了整个重排过程，同时跳过条件可见性更新。现保留字段位置，仅立即更新相关字段/高级标题的可见性。两个受影响的既有UI业务用例定向复验通过，Qt4/4。
- 原生调试01在最大化时错误检查遮罩下的辅助图入口；改为只检查实际最大化宿主。调试02初始DDC在编译占用期间未赶上通用2秒等待；本轮入口先按既有20秒数据等待预算等初始显示完成，再执行同样的稳定/GPU检查。失败报告和PNG保留，未覆盖历史结果。

最终Debug原生重开场景曾在捕获前80毫秒内遇到后续预览请求；捕获器改为在原有等待预算内观察连续80毫秒稳定，未放宽稳定/GPU条件。隔离重建后Debug完整24场景通过。

失败原始记录位于`out/tasks/ui-refinement-round2/05-acceptance/diagnostics/`，命令输出在同节点`logs/`。最终可审查副本与摘要见[evidence](evidence/)及[交付说明](DELIVERY.md)。

## 命令与证据边界

构建使用公共`vs2026-qt611-debug`、`vs2026-qt611-release` presets。全量回归由`ctest --test-dir out/vs2026-qt611-<configuration> -C <Configuration> --output-on-failure`执行，读取Qt原始日志的`FAIL!`和`Totals`，不只检查进程退出码。

本轮原生入口为`scripts/screenshot.ps1 -Configuration <Configuration> -UiRefinement -OutputDirectory <new-directory>`；正式模型旅程为`-WidebandDetection -ProductionModel`。GPU/独立启动仍使用`scripts/gpu_smoke.ps1`和`scripts/verify-package.ps1`。所有原生场景使用当次实际唯一4K/150%外接屏，全屏逻辑2560×1440、PNG物理3840×2160；未执行1366×768工作。

当前24场景入口的识别/调制/解调结果仍是明确标示的合成示例；其CPU DDC和v6重开是真实执行。正式检测43场景另行证明真实IQ、TensorRT模型前向及CPU DDC。批量G/T和真实RF精度仍由用户后续手动验证，没有新增精度或Ubuntu运行结论。
