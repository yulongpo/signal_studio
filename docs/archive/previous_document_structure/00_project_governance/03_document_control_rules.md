# 文档控制规则

## 目录职责与命名

编号目录按产品、架构、设计、接口、验证、计划和发布阶段分工；文件名使用小写英文、数字或稳定的中文业务名称，避免同义重复。模板集中于 `00_project_governance/templates/`。

## 版本、状态与审批

版本使用 `v主.次`；基线使用 `BL/AB/UB/DB/TB/RLB` 编号。状态包括草稿、待评审、已批准、实施中、待验证、已生效、已归档。正式基线和影响需求语义的变更须有可追踪审批；未知日期、负责人和结论不得猜测。

## 权威顺序

正式签署材料 → 正式需求基线 → 已批准 CR → 架构基线 → 详细设计基线 → UI/UX 基线 → 测试基线 → 开发任务和会议记录。

## 链接、编码与归档

Markdown 使用相对链接，并在提交前检查目标存在；新文档采用 UTF-8。过期草稿、被替代基线和历史评审移入 `99_archive/`，正式基线只通过 Git 移动，不得格式化改写。
